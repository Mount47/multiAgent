# Multi-Agent 后续待实现功能清单

更新时间：2026-03-12

## P0（优先级最高，建议先做）

1. 端到端联调稳定化
- 目标：在本地 Ollama 可稳定完成一次完整流程（需求 -> 架构 -> 编码 -> 测试 -> 评审 -> 通过/修订）。
- 内容：
  - 增加启动前健康检查（模型可用、工具可用、workspace 可写）。
  - 在 CLI 增加更明确的错误分类与退出码。
  - 增加最小可复现任务的集成测试脚本。

2. 工具调用能力降级策略
- 目标：当模型不支持 tool calling 时仍可运行（能力降级但不崩溃）。
- 内容：
  - 在 AgentFactory 根据模型能力动态挂载工具。
  - 为不支持工具的模型提供“无工具模式”提示与流程分支。

3. 状态机鲁棒性增强
- 目标：避免仅靠关键字匹配导致误转移/卡住。
- 内容：
  - 引入结构化输出（JSON schema）作为状态转移依据。
  - 增加 guard 失败时的回退策略与重试策略。

## P1（中优先级）

1. API 服务化落地（当前为占位目录）
- 目标：提供 REST/WebSocket 对外接口。
- 内容：
  - `src/api/routes`：任务提交、任务状态、消息流查询。
  - `src/api/websocket`：实时推送 Agent 消息。
  - `src/api/schemas`：请求/响应模型定义。

2. 持久化能力
- 目标：保存任务、状态转移、消息日志、产物文件索引。
- 内容：
  - 引入 sqlite + sqlalchemy async（项目已声明可选依赖）。
  - 设计任务表、消息表、运行表。

3. 观测能力
- 目标：支持排障与性能分析。
- 内容：
  - 结构化日志字段标准化（task_id/run_id/agent/state）。
  - 指标采集（每轮耗时、token 用量、失败率）。

## P2（增强项）

1. Memory 模块落地
- 目标：引入长期记忆与检索增强（RAG）。
- 内容：
  - 接入 chromadb（已声明 optional dependency）。
  - 按任务沉淀需求、设计、代码上下文。

2. Prompt 管理与版本化
- 目标：支持不同任务类型的 prompt 套件与 A/B 策略。
- 内容：
  - Prompt 模板参数化。
  - Prompt 版本号与回滚。

3. 安全与沙箱加强
- 目标：降低工具执行风险。
- 内容：
  - 文件写入白名单路径策略。
  - 依赖安装来源限制与审计。
  - 代码执行资源限制（CPU/内存/时间）。

## 测试计划建议

1. 单元测试
- 状态机转移、guard 判断、配置加载、工具输入校验。

2. 集成测试
- Mock 模型输出覆盖：通过路径、修订路径、失败路径。

3. 真实环境测试
- 至少覆盖一种远程 API 模型与一种本地 Ollama 模型。

## 交付里程碑建议

1. M1：P0 完成，能稳定跑通本地全流程。
2. M2：P1 API + 持久化上线，支持多任务并发查看。
3. M3：P2 memory + 安全增强，提升可用性与生产可用度。
